# Highlighted topics

The admin task page manages the ordered, at-most-two highlighted topic assignments and their shared catalogue. Assignment is by stable ID, never free text. Retiring an entry prevents new assignments but does not hide or remove existing ones. Both catalogue edits and task assignments use backend revisions; on a conflict the editor asks for an explicit refresh, which discards unsaved selections. Backend validation remains authoritative for IDs and labels.

The server actions forward the signed-in administrator's cookie, not the shared backend API key. Admin and task-list reads bypass the Next.js data cache, so API-key clients need not invalidate it after a write. Successful changes in the editor invalidate the `task-highlights` cache tag on detail requests and the relevant routes, and remove the shared task-list client query.

Catalogue entries may include an abbreviation and English name. The editor searches these as well as the Latvian name and stable ID, but selected assignments retain the full Latvian name. Task cards display a distinct abbreviation, exposing the canonical name and a distinct English name, when provided, in the native multiline title and accessible content. A title is omitted when it adds no information; an entry without an abbreviation may still expose a distinct English name. Editing can clear either optional field; archive changes omit them so the backend preserves them. Responses from older backends without these fields remain readable.

The form uses **Izceltie temati**, **Saīsinājums**, **Nosaukums latviski** and **Nosaukums angliski**. See the [project glossary](../../docs/terminology.md) for Latvian terms and abbreviation conventions.

Verify with an admin session: create a catalogue entry, assign two entries, reorder and save; reload the task list, including a task with no origin. Rename and retire an assigned entry, confirm it remains displayed but cannot be newly assigned, then remove and reactivate it. In two sessions provoke a revision conflict and verify the explicit refresh. Public task responses without `highlighted_tags` remain supported.

Signed-in users can hide highlighted topics in their account to avoid solution clues. The preference is saved through the authenticated preferences endpoint and read from `whoami` for the server render as well as the client. Older backends that omit `hide_task_tags` default to showing topics; a failed save leaves the setting unchanged. The hidden state removes the topic stack and its accessible description, while preserving solve counts and origin layout. Verify by enabling the setting, reloading the task list, and checking the initial HTML and accessibility tree; repeat after disabling it and as a guest.
